# 统一业务状态码

Business 与 Order 服务共用本状态码表。响应固定为：

```json
{"code":1000,"error_msg":"","data":{},"request_id":"..."}
```

HTTP 状态表达传输结果，`code` 表达业务结果。状态码全项目唯一，发布后不得改变含义或重复使用。默认文案由 `internal/ecode` 集中管理，Service 不得自行拼接错误文案。

| code | HTTP | error_msg | 含义 |
|---:|---:|---|---|
| 1000 | 200 | 空字符串 | 成功 |
| 1001 | 400 | 请求参数无效 | 参数解析或校验失败 |
| 1002 | 404 | 资源不存在 | 路由或业务资源不存在 |
| 1003 | 405 | 请求方法不支持 | HTTP Method 不匹配 |
| 1004 | 501 | 接口业务逻辑尚未实现 | 规划接口占位 |
| 1100 | 401 | 请先登录 | 缺少登录凭据 |
| 1101 | 401 | 登录态无效或已过期 | Token 无效或过期 |
| 1102 | 403 | 没有访问权限 | 身份或权限不符合 |
| 1103 | 403 | 账号当前不可登录 | 账号被禁用或注销 |
| 1104 | 403 | 当前身份不具备陪练角色 | 陪练身份校验失败 |
| 1105 | 400 | 请提供有效的Idempotency-Key | 幂等键缺失或非法 |
| 1200 | 401 | 微信登录凭据无效或已使用 | 微信临时 code 无效 |
| 1201 | 503 | 登录服务暂时不可用 | 登录配置或依赖不可用 |
| 1202 | 503 | 渠道服务暂时不可用 | 支付等渠道尚不可用 |
| 5000 | 500 | 系统内部错误 | 未知内部异常；详情只写日志 |

新增状态码时必须同时增加默认文案、HTTP 映射和测试。除 `1000` 外，所有状态码的 `error_msg` 都不能为空。
所有业务状态码必须在 `1000～5000` 范围内。Redis、数据库等内部依赖不可用统一返回 `5000 / 系统内部错误`，具体依赖错误只写服务端日志。
