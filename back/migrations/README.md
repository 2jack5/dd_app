# 东东电竞 PostgreSQL 迁移

55张表按业务属性拆分，表字段、注释、索引、CHECK、排斥约束及专用触发器放在所属业务文件中。跨表外键集中到最后一组，以处理账号/资源/管理员以及订单/结算间的相互引用。

## 执行顺序

|---|---|---|
| 000001 | foundation | btree_gist 扩展、共享只追加保护函数 |

| 000003 | resource | 文件资源、通知 |
| 000004 | coach | 陪练档案、申请、实名、技能 |
| 000005 | catalog | 游戏、区服、段位、分类 |
| 000006 | service | 服务、可售区服、排期、占位 |
| 000007 | order | 报价、订单、事件 |
| 000008 | payment | 支付、退款及事件 |
| 000009 | review | 评价及内容版本 |
| 000010 | aftersale | 售后工单及事件 |
| 000011 | settlement | 佣金、结算、追偿、独立补款 |

| 000013 | operation | 活动、Banner、推荐、审核、处罚 |

| 000017 | foreign_keys | 全部127个外键，包含同订单/同陪练/同游戏复合约束 |

每组包含 `.up.sql` 和 `.down.sql`：升级按编号升序，回滚按编号降序。命名可用于 golang-migrate 等支持此格式的迁移工具；尚未向后端引入迁移框架或数据库连接。

每个脚本自行包含 BEGIN/COMMIT。若选用的迁移框架已自动包事务，接入时应统一事务管理方式，避免嵌套事务。迁移角色需要创建表/函数和安装扩展的权限。全部17组成功且外键安装完成后再启用业务写入。

## Go 中读取文件

`embed.go` 提供 `migrations.Files`（`embed.FS`），只包含本目录主迁移链的 up/down 文件。data 层可以把它交给迁移工具的文件源，按版本和指定方向读取；不要把 up/down 全部当成一个批次执行。本包不自动连接数据库或在启动时执行 SQL。

原 `model.PostgreSQLSchema` 已移除，模型包仅保留模型与 `AllModels()`。本目录是迁移的唯一维护位置。

## 新库与旧库

- 新数据库：从000001执行到000017，不运行 `legacy` 下的历史补丁。
- 已通过旧版54表单文件脚本建库：`legacy/002_model_review_fixes.sql` 保留原升级补丁，单独执行一次可升级为当前55表结构；不要再重放主迁移链。
- 已通过修正版55表单文件脚本建库：本次仅拆文件，没有业务DDL变更，无需重跑 SQL。后续接入迁移工具时，确认结构完全一致后再按该工具的基线机制登记版本17。
- 不混用历史补丁的版本号和主迁移链编号。若旧库需要使用主迁移链的回滚文件，应先核对对象与基线，不能仅凭表数量判断兼容。

`legacy` 不在 embed 文件范围内，也不属于本目录编号迁移链。

## 回滚边界

回滚会删除对应业务表及数据。先回滚000017解除外键，再按编号降序回滚业务模块，最后删除共享函数；脚本不使用 CASCADE，存在意外外部依赖时应明确失败。基础回滚保留 `btree_gist`，避免删除其他 schema 可能共用的扩展。
